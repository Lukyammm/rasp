# Texto para mandar

Para mensagem que o usuário vai copiar e mandar (WhatsApp para o chefe, o cliente ou um amigo, e-mail,
perguntas para cliente) e para resposta a uma correção que chegou do chefe ou do cliente.

## Mensagem pronta para colar

- **Na voz do usuário, falando com a pessoa.** "Você", não "ela" nem "a cliente".
- **Sem frase de apresentação e sem marca de IA.** Começa pelo assunto.
- **Numeração que sobrevive ao copiar:** `1)` dentro de bloco de texto. Lista numerada do Markdown perde os
  números quando se copia.
- Sem travessão, sem emoji.
- **Negrito no WhatsApp é um asterisco de cada lado**; o `**` do Markdown chega quebrado. Usar só quando for de
  propósito.
- Curta. Se for longa: blocos curtos separados por linha em branco, um assunto por bloco.
- **Para colega ou amigo: natural, sem tópicos**, como conversa. Começar curto.
- **Mensagem de entrega acompanha o anexo:** uma por arquivo ou link, curta, dizendo o que é.

## Quando chega correção do chefe ou do cliente

- **Separar em duas partes:** o que responder (explicação de dúvida) e o que mudar na peça.
- Aplicar todas as mudanças e devolver a lista item por item com o status, para o usuário conferir que nada ficou
  de fora.
- Registrar cada correção como regra no `CLAUDE.md` do projeto (ou no `REGRAS_<ENTREGA>.md`), com data e frase.
- Dúvida do cliente sobre um número quase sempre mostra rótulo ambíguo: a resposta é mudar a peça, não só
  explicar.

## Perguntas para cliente

- Poucas e essenciais primeiro; se a lista for longa, marcar quais são as essenciais.
- Uma coisa por pergunta, com exemplo de resposta quando ajudar (ex.: *me passa a duração e o preço de cada
  serviço*).
- Guardar as respostas literais no projeto antes de usar.
